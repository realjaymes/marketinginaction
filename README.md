# Marketing In Action website

This repository holds the source for the Marketing In Action (MIA) website at https://marketinginaction.xyz. MIA is an execution-first marketing ecosystem for marketers, founders and go-to-market (GTM) operators. The site carries the MIA Academy, the consulting pages, the done-for-you outreach niche pages, free resources, jobs, and the affiliate program. The newsletter lives on Substack at https://newsletter.marketinginaction.xyz.

The site is plain HTML, CSS and vanilla JavaScript. There is no framework and no bundler. Python 3 scripts in `tools/` check and generate parts of the site.

## Structure

- `index.html`, `404.html`, `styles.css`: the home page, the not-found page and the shared stylesheet.
- `academy/`: MIA Academy offers and their pages, including `sme/` for Nigerian business owners, `dime/` and its replay and class pages, `pro-bootcamp/`, `pmm-course/` and `templates/`.
- `consulting/`: the consulting pages, case studies and the booking page.
- `acquisition/`: one landing page per local service niche, each cloned from an existing niche page.
- `resources/`: the paid ads playbook, the SEO, GEO and AEO playbook, the outbound cost calculator, the events calendar, the marketing AI tools database and the thought leaders list.
- `go/`: ad bridge pages. A bridge is a short page that sits between an ad and the page it promotes.
- `affiliate/`, `jobs/`, `services/`, `book/`, `privacy/`, `terms/`: the remaining public pages.
- `options/` and the `options/` folder inside each section: design previews that are not live pages.
- `assets/`: images and shared files.
- `data/`: data files that pages and tools read, such as `advertised-pages.json`, `dime-proof.json` and `data/resources/`.
- `tools/`: checks, generators and helper scripts (see below).
- `_redirects`: permanent redirects for old links, including the old Substack paths.
- `robots.txt`, `llms.txt`, `sitemap.xml`, `sitemap-main.xml`: crawler files.
- `PRICING.md`: the pricing catalog, generated by `tools/pricing-catalog.py`.
- `CLAUDE.md`: working notes for AI coding assistants that edit this repo.

## Preview locally

```bash
python3 -m http.server 8000
```

Then open http://localhost:8000. The built-in server does not apply `_redirects`.

## How deploys work

Cloudflare Pages serves the live site. The Pages project is connected to this repository, and every push to `main` builds and deploys. Other branches get preview builds.

The build runs `bash tools/cf-build.sh`. It runs the site checks, then rebuilds `sitemap-main.xml`. If any check fails, the build fails and the last good deploy stays live. Cloudflare also holds DNS, SSL and the redirect rule that sends `www` to the bare domain.

`_redirects` is read by Cloudflare Pages. Cloudflare applies a redirect even when a file exists at that address, and it rejects the Netlify `!` force flag, so never add `!` to a rule.

Two older hosts still have files here. `netlify.toml` belongs to the previous Netlify host, which stays available as a fallback for now. `.github/workflows/static.yml` deploys a GitHub Pages copy of the site and runs the same checks.

## Checks

The same checks run in the Cloudflare build, in the GitHub Pages workflow and in the pre-push hook. Keep the three lists in step.

- `tools/verify-calculators.py`: checks every acquisition ROI calculator against the one pricing model.
- `tools/check-wording.py`: fails on known template wording errors in cloned pages.
- `tools/check-og.py`: fails when a page's Open Graph or Twitter tags are incomplete. `tools/og-tags.py` writes the fix, and `tools/og-image.py` renders the 1200 by 630 share image.
- `tools/check-bridges.py`: fails when a page listed in `data/advertised-pages.json` has no valid bridge in `go/`.
- `tools/dime-proof.py`: keeps the DIME proof figures and screenshots in `data/dime-proof.json` in step with the seven pages that show them. Run it with `--write` to apply an update.

Enable the pre-push hook once per clone:

```bash
git config core.hooksPath .githooks
```

## Generated files

- `sitemap-main.xml` is generated by `tools/generate-sitemap.py` on every deploy from the pages on disk, with each date taken from the page's last commit. Never edit it by hand. `sitemap.xml` is the hand-written index and stays manual.
- `PRICING.md` is regenerated with `tools/pricing-catalog.py` after any price change.
- The resource pages under `resources/` are built from `data/resources/` by `tools/resources/build.py`.

## Automation

- `.github/workflows/resources-upkeep.yml` runs every Monday. It runs `tools/resources/upkeep.py`, which moves ended events out of the calendar, reads event sites for new dates, checks tool websites monthly, and saves each thought leader's latest post. It rebuilds the pages and commits the result. Anything that needs a human decision goes to `data/resources/review.json`.
- `.github/workflows/indexnow.yml` waits for a push to go live, then tells Bing and other IndexNow search engines which sitemap pages changed, using `tools/indexnow.py`.
- `tools/resources/intake.py` and `intake-run.sh` add new events and tools from a daily intake run.

## Other tools

- `tools/check-hosting.py` records how a host answers every redirect and sitemap page without following redirects, and compares two hosts. Use it to prove a hosting change leaves every address behaving the same way.
- `tools/preview-parity.py` and `tools/theme-preview.py` support design previews.
- `tools/page-qa.mjs` and `tools/page-shot.mjs` are Node scripts for page checks and screenshots.

## Conventions

- Pages are built by cloning an existing page, so styles, navigation, footer, analytics and checkout wiring stay the same.
- A page needs a bridge at `go/[slug]/` only if it runs paid ads. Acquisition niche pages and resource pages never get one. List the page in `data/advertised-pages.json` before its first ad goes live.
- Bridges and other pages that should stay out of search use a `noindex` robots meta tag only. `robots.txt` carries no Disallow rule, because a Disallow would stop the crawl and the tag would never be read.
- DIME proof figures are never typed into a page. They come from `data/dime-proof.json` through `data-proof` markers.
- Analytics runs through Google Tag Manager and Google Analytics 4, with Meta and TikTok pixels on the sales pages.
